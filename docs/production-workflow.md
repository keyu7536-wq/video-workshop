# 视频工坊：输入、制作与输出

视频工坊把文案、文章、论文与已有素材整理成可编辑的视频项目。它调用模型理解资料和安排分镜，调用语音服务配音，最后在本机用 FFmpeg 合成。它不是从一句话直接生成所有新画面的文生视频模型。

## 输入什么

| 输入 | 程序如何处理 |
| --- | --- |
| 已写好的文案 | 按段安排镜头；选择保留文案时，校验文字不被模型擅自改写 |
| 文章正文或可访问链接 | 提取资料，生成讲述文案与分镜；事实仍需要来源支持 |
| 论文 PDF | 提取文字与页面图像，可开启论文深读和作者项目研究 |
| 图片、视频 | 读取素材、抽帧供模型选择，支持图表裁切、高亮和视频取段 |
| 多种输入组合 | 建立统一来源编号，使文案依据和画面来源可追溯 |

链接必须可由程序访问。需要登录、动态加载复杂或限制下载的网站可能无法读取；此时可提供本地文件或可直接下载的地址。缺少素材会记录为缺口，不表示已经搜索了全网。

## 界面的三步

1. **添加资料：** 编辑输入、创作要求、画幅和声音；从旧任务修改资料后重新生成，会另建任务并保留原记录。
2. **文稿与分镜：** 默认等待人工确认。可以修改段落和镜头，播放原视频的所选片段，调整图表裁切；保存后再生成。允许自动返修时，程序会保存修订记录，已有文案仍受保护。
3. **预览与导出：** 查看实际成片与各镜头片段、复核结果和导出文件。可以返回第二步继续编辑，重新生成后才得到与修改一致的新片。

自动直出和自动返修均是可选项；选择自动直出会跳过第二步的等待。下列是三步界面内执行的处理环节，不是六个人工操作步骤。

## 程序怎样处理资料

1. **整理资料。** 文件复制到独立任务目录；论文、图片、视频和正文分别解析。开启联网研究时，程序从论文链接和标题查找作者项目，再核对作者、任务和论文身份。
2. **形成研究笔记。** 论文模式整理问题、旧方法瓶颈、输入输出、机制、实验、限制和代码线索。仓库只读取 README、许可与选择的相关文件，不执行下载的代码。普通文章和自带文案不强行套论文模板。
3. **写稿与分镜。** 论文讲解应尽早介绍论文、团队与研究任务，再解释旧瓶颈、方法和证据；画面对应正在讲的观点。编辑器允许改稿、换素材、调整取段和图表区域。
4. **复核计划。** 检查引文、数字、素材关系与讲述连续性。明确事实错误会阻止直接进入自动成片；风格建议与抽帧局限单独记录。
5. **配音和时间线。** 根据实际录音长度安排画面与字幕，而不是把目标秒数当成固定片长。同文案、音色和语速可复用配音缓存。固定语速与自动节奏是不同选项；使用哪一种应保持为任务设置。
6. **合成与复查。** 检查可解码视频、非静音音轨和画幅；开启成片复查时，对实际编码帧、叙事和时间线分别审核。同一输入全流程共用最多 3 次修订生成额度，失败也计数；每轮保留候选、意见和回滚副本。审核不可用时停止生成并保存候选供续审；次数耗尽仍未解决的问题保留为待复核状态。

上述步骤都由工作台调度执行，不需要另开 Codex 对话手工下载、改计划或合成视频。Codex CLI 或模型 API 负责模型调用；资料处理、时间检查、修复条件、缓存、FFmpeg、审核状态和导出由项目代码管理。

## 失败时怎样继续

- 文稿与分镜未完成：打开原任务点“继续生成文稿与分镜”，已有资料和有效阅读缓存会复用。
- 镜头比实际配音短：程序先用同段已经选定的相关静态图承接。没有可用画面，或完整动作与语音切点冲突时，收集全部缺口交模型重新安排镜头，消耗全流程共享的修订额度；不改原文稿，不以慢放、循环或长文字卡填补。
- 合成失败：任务页保留真正原因，详细日志在 `analysis/render.log`。修正条件后点“重试生成视频”，已有配音缓存可复用。
- 只有附加格式导出失败：点“重试导出”，直接使用已有成片，不重新编码全部画面。
- 审核服务暂时不可用：成片保留为待复核，可点“重试成片复查”。如果之后修改了文稿、配音或画面设置，必须重新生成对应视频，不能拿旧片通过新计划的审核。

自动修复有次数上限；仍有问题时保留明确诊断和可编辑计划。程序不会把服务故障、未运行的审核或不完整的画面抽样记作通过。

## 画面与声音约定

- 横屏、竖屏、方形或自定义尺寸由任务选择；保留完整素材与居中裁切的效果不同，生成前应查看预览。
- 章节标题直接写内容。默认不使用“先讲清：”“核心想法：”这类讲述提示，也不把配音名称、审核指令或制作说明烧录到画面。
- 以演示、图表和相关插图为主，避免大段文字卡。默认结束在最后相关镜头，不自动追加配音说明或总结片尾。
- 来源页码、取段时间、研究缺口与复核记录放在随片文件；必要的事实限定仍应保留，例如仿真与实机、训练与测试的区别。
- 音色和语速可配置，不把某条演示的配音作为通用强制设置。正式配音与试听应使用相同参数。生成式音色可能在不同段落出现差异，独立转录只能核对内容，不能证明听感自然。

## 输出什么

每次任务保存在 `jobs/<任务编号>/`，不会要求携带任何演示论文或私人样片才能使用。

| 文件 | 用途 |
| --- | --- |
| `request.json` | 任务输入和公开配置，不保存界面 API Key |
| `analysis/sources.json` | 资料编号、摘录、素材位置与来源信息 |
| `research.json`、`research.md` | 开启深读时形成的研究笔记 |
| `analysis/studio_plan.json` | 可编辑的讲述段落、证据与镜头计划 |
| `project.json` | 渲染器使用的配音、画幅和时间线配置 |
| `narration.txt`、`evidence.json` | 讲解稿与引文、裁切依据 |
| `output/video.mp4` | 带配音与字幕的成片或待复核草稿 |
| `output/subtitles.srt`、`output/narration.wav` | 单独字幕与配音 |
| `output/run_report.json` | 实际时长、分辨率、配音设置与缓存信息 |
| `output/final_review.json` | 开启成片复查时生成的版本绑定复核结果 |
| `publishing.json` | 可编辑的发布标题与简介；生成此文件不会自动发布 |

按需还可导出 MOV、WebM、MP3、VTT 与项目 ZIP。项目 ZIP 包含用户任务的素材和记录，用于继续编辑；它与不含私人任务数据的开源源码包不同。实际生成的格式以编辑器下载列表为准。

## 模型与服务

可选本机已登录的 Codex CLI，或支持图片与结构化输出的兼容模型 API。制作规范、来源数据和审核规则保存在项目内，供两条路径共用。更换模型后仍须用代表性案例验证，不能据此保证不同模型产生完全相同的质量。

Edge TTS 需要联网。可选本地语音链路需要额外环境、模型与硬件准备；安装基础程序并不等于本地语音模型已经可用。语言模型账户与语音服务的身份凭据相互独立。
