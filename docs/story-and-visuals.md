# 让故事和画面真正解释内容

视频里出现了论文名、方法图和几个实验数字，不等于观众已经理解研究。v7 制作规范根据素材、受众和时长安排讲述，在可读性、解释深度和观看节奏之间取得平衡。视频工坊面向论文、文章、文案和媒体等多种输入，不让所有视频套同一种结构。

## 根据内容安排讲述

论文和研究解读可用五个问题检查覆盖是否充分：**常见方法、具体问题、本文解决什么、方法怎样起作用、效果如何**。这些问题不是固定顺序，也不意味着旧方法必须占很大篇幅；交代到足以理解本文即可。

| 覆盖问题 | 按所讲内容选择需要交代的关系 |
| --- | --- |
| 常见方法 | 观众理解改动需要哪些已有方法或知识背景；可以一句带过，也可以融入机制比较 |
| 具体问题 | 哪个步骤或假设造成什么成本、失败或限制，不能只说任务很难 |
| 本文解决什么 | 作者针对哪个问题作出什么改变，区分新贡献与沿用的基础组件 |
| 方法怎样起作用 | 改动怎样对应所讲收益；必要时用“没有这项改动会怎样”帮助解释，而不强求每次使用 |
| 效果如何 | 哪个指标、基线和实验条件检验了这种改善，结论适用于什么范围 |

根据材料和受众自动选择顺序，合并相关环节，并调整篇幅。可以先展示结果再解释方法，也可以把旧方法放在比较新机制时简要交代。`problem_solution` 是可选结构，不是默认强制流程。短篇或片段只需讲清所选内容，保留理解核心主张所需的前因后果，不要求每次展开五项。推想“不作这项改变会怎样”也不代表论文真的做过该消融实验。

完整论文解读要尽早介绍论文、团队和研究任务。开场动作、疑问和具体例子都可根据内容使用，让抽象关系更容易理解，同时让观众知道这与所讲研究有什么关系。不要因为某种场景容易画，就偏离文章真正要讲的内容。

普通文章按照自身的论证、时间或因果结构组织，不强套论文框架。用户提供的文案默认保持原文，只有明确要求改写时才修改；已标明范围的片段也不按完整论文解读要求补齐所有环节。

每场在规划时回答以下问题：

| 规划问题 | 应落到的实际内容 |
| --- | --- |
| 这一场对整段内容有什么作用？ | 补充必要背景、解释关系、展示行为或提供依据，而非凑齐固定环节 |
| 观众现在不明白什么？ | 下一段旁白要回答的具体疑问 |
| 看完这一场多理解了什么？ | 一个新的事实、步骤或因果关系，不只是一个新术语 |
| 画面承担什么任务？ | 展示真实行为、解释机制，或提供实验依据 |

这些信息可以保存在每段的可编辑 `explanation` 字段中。它用于安排镜头，不会自动写进旁白或烧录成画面标题；旧项目缺省为 `null`，不需要为了打开旧项目补造内容。

| 字段 | 内容 |
| --- | --- |
| `question` | 观众在本段需要弄明白的具体问题，最多 240 字 |
| `takeaway` | 看完应理解的事实或关系，最多 320 字 |
| `visual_strategy` | `demonstration` 行为演示、`comparison` 对比、`process` 过程、`timeline` 时间线、`data` 数据、`context` 背景六选一 |
| `continuity` | 与前后段沿用的对象、例子或逻辑联系，最多 240 字；不需要时可留空 |

填写这些字段不代表已经讲清楚，也不要求每段以问句开头。应对照实际文案，选择具体素材、镜头和旁白切入点。受保护文案的文字和顺序不随字段编辑而改变；普通文章也不会因为这些字段而变成论文模板。

只讲一个组件的输入和输出，通常还没解释为什么它能解决问题。必须补上这个操作与原有瓶颈之间的关系，并区分作者的机制解释与实验已经证明的结果。只有研究确实涉及学习系统时，才需要相应解释反馈、参数更新或训练与使用阶段的区别。

## 让画面跟着操作走

画面服务于当前的解释。讲新旧方法的差别时，保留可比较的角色和名称，突出改变的位置；讲结果时，展示真正支持主张的图表或观察。无需给每条视频安排新旧对照。方法图采用短标签与有意义的箭头，按旁白逐步突出实际存在的处理关系。只有确实存在反馈的过程才画返回路径，不给所有研究都套上循环图。

用到具体例子时，尽量沿用相同术语和视觉角色，但画面不能只演示例子而遗漏研究贡献。作者演示说明实际观察到的行为；概念流程图说明操作关系；图表和对照实验才支持相应的结果主张。概念动画里的移动点不是实测延迟、物体轨迹或实验成功率。不要一次堆满所有模块，也不要用持续移动的装饰元素代替解释。

先检查已经取得且实际查看过的相关原片，再决定动作是否适合用静图讲。下载成功不等于看过，也不要求为了凑比例用完全部视频。一个段落如果依次解释行为、机制和结果，可以按旁白切换对应素材，不能让一张曲线图长期承载它并未说明的操作。选择不用相关素材时，应记录具体原因，而不是把“有素材”当成“已充分利用素材”。

阶段切换应使用实际配音的时间点，并在最终编码画面上复查。旧计划中的 duration 可能只是分配权重，不能据此声称画面准确停留了某个秒数。

少文字选项约束最终可见内容，不只约束程序生成的文字卡。论文正文和网页段落截图也不能用来填满画面：原文引文保留在证据文件中，视频优先展示对应行为、相关图的局部或诚实的解释示意。必要的短引句可以展示，但要有对应讲解和读完的时间；图表的坐标、图例和比较条件不能删掉。

超宽拼图应按当前讲述选择单幅或相邻两幅，必要时按配音连续切换局部。检查的是动作、对象和差异能否辨认，不是背景有没有铺满；高亮框和模糊填充不会扩大主体。宽图、静态图和留白本身不是错误。只有实际内容违反明确的少文字要求，或关键行为/关系因缩得太小而无法理解，才根据具体镜头、时间、旁白和画面记为错误；次要标签或构图偏好按影响提出建议。

## 原图定位与局部放大

页面和图片镜头可用 `visual_beats` 指定按旁白推进的观察范围。先给观众足够的原图上下文，再放大正在说明的局部；移动和放大本身不证明任何结果。

```json
{
  "visual_beats": [
    {"cue": "", "bbox": [0, 0, 1, 1], "label": "完整对比图"},
    {"cue": "左侧这一组", "bbox": [0, 0, 0.5, 1], "label": "左侧结果"}
  ]
}
```

这是字段示例，不是通用裁图建议；“左侧这一组”必须确实在当前段落的旁白中唯一出现。计划中的 `bbox` 坐标相对完整原始页面或图片，范围为 0～1，且必须位于镜头本身的裁图范围内；镜头未设裁图时使用完整原图。上例只有在镜头包含整图且局部保留了必要条件时才适用。导出时再转换为准备后的镜头图片坐标。

第一阶段 `cue` 为空，后续阶段按本段旁白中出现的先后排列，并位于该镜头的旁白窗口内。只支持 `page` 和 `image`，不能与 `focus` 或 `column_crop` 同时使用。放大不能删掉理解主张必需的坐标轴、图例、条件或对照；需要时先保留可读的全图说明。计划预览不代表最终运动和字幕效果，仍须检查按配音生成的实际阶段画面。

## 开发者：生成分阶段流程图

[`studio_diagrams.py`](../studio_diagrams.py) 接收节点、箭头和阶段时间，输出无声 MP4，供视频流程合成旁白与字幕。它负责绘制已确定的关系，不负责判断论文中的科学事实。下面仅演示流程图接口，不是要求所有论文采用动作反馈循环；时间为演示值，用于正式视频时应换成对应旁白的实测秒数。

```python
from studio_diagrams import render_diagram, render_frame, validate_graph

spec = {
    "title": "动作怎样得到改进",
    "note": "流程示意",
    "nodes": [
        {"id": "act", "label": "做出动作", "x": .18, "y": .42},
        {"id": "observe", "label": "观察结果", "x": .50, "y": .42},
        {"id": "update", "label": "调整参数", "x": .82, "y": .42},
    ],
    "edges": [
        {"id": "trial", "source": "act", "target": "observe"},
        {"id": "feedback", "source": "observe", "target": "update"},
        {"id": "next", "source": "update", "target": "act",
         "label": "下一次尝试", "via": [[.82, .67], [.18, .67]]},
    ],
    "stages": [
        {"start": 0, "visible_nodes": ["act"], "active_nodes": ["act"]},
        {"start": 2, "visible_nodes": ["act", "observe"],
         "active_nodes": ["observe"], "active_edges": ["trial"]},
        {"start": 4, "active_nodes": ["update"], "active_edges": ["feedback"]},
        {"start": 6, "active_nodes": ["act"], "active_edges": ["next"]},
    ],
}

validate_graph(spec, duration=8)  # 检查结构，不代表科学内容已经审核
render_diagram(spec, "output/diagram.mp4", duration=8)
render_frame(spec, time=4.5, duration=8).save("output/diagram-preview.png")
```

节点坐标按整个画布的宽高归一化。节点中心使用 `x=.13～.87`、`y=.26～.70`，底部 22% 留给合成后的字幕；同时可见的节点不能重叠。节点可另设短说明 `detail`，箭头可设 `label` 和转折点 `via`。多种比例都需要单独检查最终可读性。

`via` 最多 8 个 `[x,y]` 折点，每点须满足 `x=.025～.975`、`y=.18～.78`，包含边界。它们与节点使用相同的全画布坐标，但必须留在图形安全区；越界诊断会给出边的 id、折点序号、当前坐标与允许范围。

阶段的 `start` 是相对本段素材的秒数，第一阶段从 0 开始，后续严格递增且小于总时长。`visible_nodes` 省略表示全部节点可见，空列表表示全部隐藏；`active_nodes` 和 `active_edges` 控制强调，活跃箭头两端的节点必须可见。规划阶段可暂用 `cue` 标出旁白锚点，正式渲染前必须将每个阶段解析为真实的 `start`；结构校验会保留尚未解析的时间，不能将只有 `cue` 的计划直接用于成片。

`render_frame` 返回 PIL 图像，`render_diagram` 返回文件、实际帧对齐时长、帧数、帧率、分辨率、图结构摘要及素材性质说明。两者支持 `width`、`height`、`font`；视频函数还支持 `fps`、`ffmpeg`。图中的移动点仅表达概念上的信息传递。

## 检查什么

内容复核先尝试复述这条视频实际要讲的内容，检查必要背景、核心关系和依据是否足够。只有缺失连接导致核心主张误导、缺乏支持或无法理解时，才作为错误，指出具体段落、缺失关系及来源。旧方法讲得简短、顺序不同或略去次要背景不自动算错误；补充后确实有助于理解时，给出具体改进提示。不能为了凑齐五项，让文章、文案或片段失去原有结构。

`explanation` 是待核对的规划意图，不是证据。审核应对照实际旁白、所选素材和画面检查问题是否得到回答，不能因为字段完整就通过，或因为旧项目没有字段就阻断。没有拿到可播放的参考视频时，只能说明拿到了链接或其他已读取信息，不能声称看过其剪辑、动态画面和配音，也不能保证自动达到某位作者的水平。

画面复核检查旧操作与改动是否对应、箭头方向和概念角色是否正确，以及关键阶段是否在对应旁白出现时可辨认。只有相关方法涉及训练与部署时，才检查二者区别。结果复核检查指标是否真的对应所讲收益、比较条件是否保留，不能把未经控制的比较说成某个组件产生效果的证明。错误关系或误导性主张需要修正；字号略小、静态画面偏长、次要标签不突出等问题，按实际影响记录改进提示。

制作合同和审核规则分别位于 [production.md](../skills/paper-video-director/references/production.md) 与 [review.md](../skills/paper-video-director/references/review.md)。它们规定的是规划和复核标准，不保证任何模型一次就能得到高质量故事，也不把格式正确等同于解释正确。
